### 2. Upgraded Embedding Model
**Commit `6ac4b63` on `main`, pushed to fork.**

Replaced the 2021-era MiniLM model with a dramatically better one:

| | Before | After |
|---|---|---|
| Model | Xenova/all-MiniLM-L6-v2 | nomic-ai/nomic-embed-text-v1.5 |
| Package | @xenova/transformers v2 | @huggingface/transformers v3 |
| Dimensions | 384 | 256 (Matryoshka truncation) |
| Max tokens | 256 (~200 words) | 8,192 (~6,000 words) |
| MTEB retrieval | 41.95 | 62+ |
| ONNX variant | fp32 (23MB) | q8 quantized (137MB) |
| Text truncation | 2,000 chars | 8,000 chars |

Key technical details:
- **Task prefixes** added: `search_query: ` for queries, `search_document: ` for indexing (required by nomic)
- **Matryoshka truncation**: slices 768-dim output to 256 dims, then L2 re-normalizes
- **q8 quantization**: fp32 model (547MB) caused onnxruntime protobuf parsing failures; q8 works perfectly
- **Auto DB migration**: `initDatabase()` probes vec_exchanges dimension, drops/recreates on mismatch
- **`@ts-expect-error`** on `pipeline()` call — v3's overloaded types are too complex for TypeScript inference
- Constants (`EMBEDDING_DIM`, `EMBEDDING_MODEL`) in `src/constants.ts` — avoids circular dependency between db.ts and embeddings.ts

## Setup on Mac Mini

### Step 1: Clone and Build
```bash
git clone git@github.com:kevinmatspie/episodic-memory.git ~/repos/local/episodic-memory
cd ~/repos/local/episodic-memory
npm install && npm run build
```

### Step 2: Install as Claude Code Plugin
The project is structured as a Claude Code plugin (`.claude-plugin/plugin.json`). To install from a local directory:

```bash
# From within any Claude Code session on the Mac mini:
/install-plugin ~/repos/local/episodic-memory
```

Or add it to your settings manually. The plugin provides:
- **MCP server** with `search` and `read` tools
- **SessionStart hook** that runs `sync --background` to index new conversations
- **Search agent** for guided conversation recall

### Step 3: Initial Sync
```bash
cd ~/repos/local/episodic-memory
node cli/episodic-memory.js sync
```

This will:
1. Copy conversations from `~/.claude/projects/` to `~/.config/superpowers/conversation-archive/`
2. Generate embeddings (first run downloads the ~137MB q8 model)
3. Index into SQLite at `~/.config/superpowers/conversation-index/db.sqlite`
4. Generate summaries for up to 10 conversations per run

Run `sync` a few more times to catch up on summaries, or just let the SessionStart hook handle it over subsequent sessions.

### Step 4: Verify
```bash
# Check stats
node cli/episodic-memory.js stats

# Try a search
node cli/episodic-memory.js search "some topic from your conversations"

# Check index health
node cli/episodic-memory.js index --verify
```

## Git Remotes
```
origin  → git@github.com:obra/episodic-memory.git   (upstream, read-only)
fork    → git@github.com:kevinmatspie/episodic-memory.git (your fork)
```

On the Mac mini clone, `origin` will point to your fork. If you want to track upstream too:
```bash
git remote add upstream git@github.com:obra/episodic-memory.git
```

## Excluding Projects from Indexing
If you don't want certain projects indexed:
```bash
echo "project-name" >> ~/.config/superpowers/conversation-index/exclude.txt
```

## Architecture Quick Reference
```
~/.claude/projects/          ← Claude Code writes conversations here
        ↓ (sync)
~/.config/superpowers/
├── conversation-archive/    ← Archived copies (organized by project)
└── conversation-index/
    ├── db.sqlite            ← Search index (exchanges + vec_exchanges)
    └── exclude.txt          ← Projects to skip
```

## What's Next
Potential improvements discussed but not implemented:
- The summaries are still generated by the upstream's Claude API calls — may want to configure `EPISODIC_MEMORY_API_*` env vars if you have a preferred endpoint
- Could further tune the embedding dimension (256 was chosen as a good balance; 384 or 512 are options if search quality seems insufficient)
- The similarity percentages shown in search results are relatively low (this is normal for cosine similarity with dense embeddings — ranking order matters more than absolute percentages)
